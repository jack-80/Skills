# 报告结构、图表清单与写作口径

两份产物内容一致、详略不同：

- **HTML 报告**（`amazon_<ASIN>_report.html`）——沉淀与分享，由 `build_report.py` 生成，自包含单文件。
- **对话内 Markdown 简报**——即时阅读，含摘要 + 横向/纵向对比表。

需要把数据交给用户自己再算（透视表、二次建模）时，用 `--csv` 额外输出 CSV 包，含对比表与原始序列。

## 一、章节顺序

只有拿到数据的章节才会出现在报告里；标题自动编号，不要手写编号。

| # | 章节 | 内容 | 数据来源 |
|---|------|------|----------|
| 1 | 执行摘要 | 一句话结论、关键数字卡、洞察、行动建议、风险 | `summary` |
| 2 | 产品概览 | 价格/星级/评论/BSR/变体/配送/Listing 完整度 | `snapshot` |
| 3 | 价格与促销 | 价格走势、30 天均价、高低点、促销记录 | `price` |
| 4 | 排名与销量 | BSR 走势（反向轴）、月销与 GMV、估算方法 | `rank`、`sales` |
| 5 | 评论与口碑 | 星级分布、评论增长、近 30 天新增与均分、正/负向主题 | `reviews` |
| 6 | 流量与关键词 | 会话、转化率、自然/广告占比、ACOS/TACOS、关键词流量 | `traffic` |
| 7 | 竞品对比（横向） | 对比表 + 价格/星级/评论数/BSR 四图 + 定位散点图 | `competitors` |
| 8 | 品类基准达标 | 逐项差距与达标判定 | `benchmark` |
| 9 | 纵向对比（本期 vs 上期） | 变化率表 + 分组柱状图 | `trendCompare` |
| 10 | 利润与成本 | 售价拆解、毛利/净利率 | `economics` |
| 11 | 库存与补货风险 | 可售天数、在途、断货风险 | `inventory` |
| 12 | 数据质量与缺口 | 来源与置信度、缺口清单、缺口对结论的影响 | `sources`、`gaps` |
| 13 | 方法与假设 | 估算口径、站点与汇率假设 | `methods` |

## 二、图表清单（全部内联 SVG，离线可用）

| 图表 | 触发条件 | 要点 |
|------|----------|------|
| 价格走势折线 | `price.series` ≥2 点 | 标出最高/最低点 |
| 月销量柱状 | `sales.monthly` | 图注写明估算方法与置信度 |
| BSR 走势折线 | `rank.series` ≥2 点 | **反向轴**：数值越小画得越高 |
| 星级分布柱状 | `reviews.starDistribution` | 5★→1★ 顺序，1★ 用警示色 |
| 评论增长折线 | `reviews.history` ≥2 点 | 可与评分做双轴 |
| 关键词流量横向条 | `traffic.keywords` | 按流量占比排序取前 8–10 |
| 竞品价格/星级/评论数/BSR 柱状 | `competitors` 非空 | 评论数用对数轴；价格带基准参考线 |
| 价格 × 评分定位散点 | `competitors` 非空 | 气泡大小 = 评论数，画中位线 |
| 本期 vs 上期分组柱状 | `trendCompare.rows` | 每项一组 |
| 利润拆解条 | `economics` | 售价 → 各项扣减 → 净利，横向可比 |

图注规则：每张图配一句解读，不要只放图。BSR、对数轴、估算值、币种这四处必须标注。

竞品对比的标注约定（由 `build_report.py` 自动处理）：

- 对比表列头为「品牌 / ASIN」两行；柱状图横轴第一行品牌、第二行 ASIN；散点图气泡标签用品牌，图注指向对比表。
- 竞品缺 `brand` 时自动降级为只显示 ASIN，不猜品牌。
- **某个指标只有本 ASIN 有值时不画对比图**（避免"只有一根柱子的伪对比"），只在图注里说明哪些指标未做横向对比，
  并把这些缺口写进 `gaps`。
- 「竞品中位」只统计竞品，不含本 ASIN；价格图的基准参考线与表内中位值必须一致。
- `snapshot.returnBadge` 存在时，页头与「产品概览」都会高亮退货标记。

## 三、三要素硬约束

交付前逐条确认，缺一不可：

1. **总结**——有执行摘要，含一句话结论 + 洞察 + 分级行动建议 + 风险。
2. **图表**——至少 4 张，含至少一张对比类图表。
3. **数据对比**——横向（vs 竞品 vs 品类基准）与纵向（本期 vs 上期）都要有；
   纵向数据确实拿不到时，必须在 `gaps` 里写明缺什么数据、以及这个缺口会让哪条结论不成立。

## 四、写作口径

- 语言：简体中文；ASIN、BSR、Buy Box、FBA、ACOS、TACOS、A+ 保留英文。
- 数字：价格带币种；百分比 1 位小数；缺失用「—」，并在数据质量章节说明原因。
- 结论：每条洞察都要挂数据依据，写成"数字 + 判断"，不写"表现良好"这类空话。
- 建议：面向运营者可执行——定价、评论获取、Listing 优化、广告结构、库存补货，
  每条写清优先级与预期影响。
- 立场：不粉饰。数据不支持的乐观结论不要写。
- 篇幅：HTML 报告可展开；对话简报每节 3–6 行。

## 五、交付前自检

- [ ] `validate_data.py` 无 error（warning 已逐条确认或补进 `gaps`）
- [ ] 每个数字都能追到 `sources`，估算值都标了方法与误差
- [ ] 执行摘要里的每个数字与正文章节一致（不要两处对不上）
- [ ] **价格是与目标市场同口径取的**（本地配送地 + 本地语言），`sources` 里写明了配送地与语言
- [ ] **竞品与目标同形态**（多件套只比多件套），头部参照品没有被混进中位数基准
- [ ] 每个竞品都带品牌；页面未标注品牌的已留空并说明，没有猜
- [ ] 退货标记（如有）已写入 `snapshot.returnBadge` 并在报告中高亮
- [ ] BSR、对数轴、估算、币种四处标注齐全
- [ ] 支付类促销（开卡立减等）没有被记成商品折扣
- [ ] 横向与纵向对比都存在，或缺口已写明
- [ ] HTML 用绝对路径交付，并已打开预览确认渲染正常

## 六、HTML 交付

- 生成命令见 `SKILL.md`；产物是**自包含单文件**：无外链、无 CDN、无网络依赖，双击即可打开，也可直接发给同事。
- 报告自动适配系统深色模式，含打印样式。
- 原始数据 JSON 会内嵌在 HTML 底部注释里，便于复核与复现。
- 生成后用环境里的预览工具打开（Codex 用 `open_in_codex`），确认图表正常渲染再交付。

## 七、CSV 交付（可选）

`build_report.py --csv <dir>` 写出以下文件，编码 UTF-8 BOM，Excel 打开中文不乱码：

| 文件后缀 | 内容 |
|----------|------|
| `_kpi` | 执行摘要的关键数字与变化 |
| `_competitors` | 目标 vs 各竞品 vs 竞品中位 |
| `_benchmark` | 品类基准逐项差距与判定方向 |
| `_trend_compare` | 本期 vs 上期 |
| `_keywords` | 关键词、搜索量、排名、流量/点击/转化份额 |
| `_economics` | 价格拆解与利润率 |
| `_price_series` / `_bsr_series` / `_review_history` / `_sales_monthly` | 图表背后的原始时间序列 |
| `_gaps` | 数据缺口清单 |
