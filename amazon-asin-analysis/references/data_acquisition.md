# 取数阶梯、本地文件解析与降级策略

目标：在"用户只给一个 ASIN"的前提下，尽可能拿到高精度数据；拿不到时诚实降级，而不是编数。

## 零、先花两分钟找本地数据

很多情况下用户手里已经有数据，只是没说。**开工先扫一遍**，命中率最高的位置：

| 位置 | 常见文件 |
|------|----------|
| 当前工作区及其子目录 | `*.csv`、`*.xlsx`、`*.json`，文件名含 ASIN、关键词、报表日期 |
| `~/Downloads` | Seller Central / 卖家精灵 / Helium 10 / Keepa 导出的原始文件 |
| `~/Documents`、`~/Desktop` | 业务报告、广告报表、产品调研表 |

搜索示例（`rg` 优先）：

```bash
rg --files -g '*.{csv,xlsx,xls,json,tsv}' /path/to/workdir
find ~/Downloads -iname "*<ASIN>*" -o -iname "*business*report*" -o -iname "*keepa*" | head -40
```

命中后**打开确认真实结构再解析**，不要凭文件名猜字段。xlsx 用 `openpyxl`/`pandas`（环境里有），csv 用标准库 `csv`。注意：

- Keepa 导出的时间列是"分钟偏移"（0 = 2011-01-01），不是日期，必须换算。
- Seller Central 报表常带表头前若干行说明文字，`header` 要往后找。
- 币种、单位（件/千件）、百分比（0.15 还是 15）三处最容易搞错，必须肉眼核对几行原始值。

## 一、取数阶梯

按顺序尝试，**上一级拿不到才降级**，每次降级都在报告里留痕。

| 级别 | 来源 | 可得字段 | 置信度 |
|------|------|----------|--------|
| 1 | 用户本地导出文件 | 取决于文件：可含历史价格/BSR/评论、真实销量与广告数据 | 高 |
| 2 | 已连接的连接器 / API（Keepa、Helium 10、Jungle Scout、卖家精灵等，仅限环境里真实存在且已授权的） | 历史曲线、评分分布、类目排名 | 高 |
| 3 | 公开页面（商品页、评论页、类目 Best Sellers） | 当前快照：价格、评分、评论数、BSR、变体、优惠券 | 中 |
| 4 | 用户补充提供 | 任意 | 用户说了算，注明"用户提供" |

### 关于第 3 级（公开页面）

- 只用环境里**实际存在**的浏览器能力；需要授权时先申请授权，不要假装已经联网。
- Amazon 对自动化访问拦截严格：商品页可能返回验证码，评论页通常需要登录。
  **失败一次就降级**，不要换关键词反复重试、不要尝试绕过反爬或登录墙。
- 抓到的必须是快照：记录抓取时间，价格与 BSR 波动大，必须标"快照时间"。
- 页面上的数字优先于聚合站的数字；第三方聚合站的估算必须标"第三方估算"。

### 口径硬要求：站点 / 配送地 / 语言

用浏览器取公开页面前，**先确认这三项，再开始记录任何数字**：

| 项 | 要求 | 不满足的后果 |
|----|------|--------------|
| 站点 | 目标站点（默认 amazon.com 美国站） | 拿错国家站的排名与价格 |
| 配送地 | 目标市场本地地址（美国站填美国 ZIP，如 10001） | 页面按跨境口径显示：价格变成本币折算价并另计进口费，本地标记（如退货标记）与促销信息也可能不同 |
| 语言 | 目标市场语言（美国站用英文） | 标题被翻译，看不出堆词问题；页面结构与字段名也可能不同 |

操作路径：页面顶部「Deliver to / 配送至」→ 打开弹层 → 在**美国邮编**输入框填目标 ZIP → 点「设置 / Done」区，
而不是弹层底部的「完成 / Close」。改完**重新加载页面再读数**，并回读一次「Deliver to」确认已切换。

注意：这类跨境状态由 Amazon 的会话 cookie 决定，**只改 URL 参数（如 `?language=en_US&currency=USD`）不会生效**——
配送地一旦是境外，币种和语言会被跨境口径覆盖。

口径不一致会直接产出错误结论。实测例子：同一个 ASIN，在"配送到中国大陆 + 中文界面"下价格显示 ¥536.63、
标题是中文翻译；切到美国本土口径（New York 10001 + 英文）后是 $79.99 与英文原标题。用前者的价格做对比得到的
价差是 +63%，后者是 +67.7%；更严重的是竞品集合形态不同，导致"评论资产是竞品 5.8 倍"这个结论在正确口径下
其实是 1.3 倍——**数字没编，口径错了，结论就全错**。所以每次取数都要在 `sources` 里写明配送地与语言。

### 价格与标记的几个坑

- **支付类促销不是商品折扣**：「Get $50 off instantly… upon approval for Amazon Visa」这类是信用卡开卡权益，
  不能记成 Coupon 或划线价，`snapshot.coupon` 要如实写"无商品折扣"。
- **变体价差常被忽略**：除当前 ASIN 价外，尽量记录变体价带（最低–最高），写进 `snapshot.variantPriceMin/Max`。
- **退货标记要单独记**：页面上出现「Frequently returned item / 经常退货的商品」时写入 `snapshot.returnBadge`。
  这是转化与退货风险的一手信号，且亚马逊不公开具体退货率，报告里只能定性、不能给数字。
- 竞品与目标必须**同一站点、同一配送地、同一语言**下取数，否则价格与显示口径不可比。

## 二、四级都拿不到时的兜底产出

这不是失败，是常态。此时仍然要交付完整报告：

1. 照常生成 HTML——框架、章节、图表占位、"待采集"标记齐全。
2. 输出**待补数据清单**，写到用户能直接执行的程度：

| 需要的字段 | 从哪导出 | 路径 |
|------------|----------|------|
| 真实销量、会话数、转化率、退货率 | Seller Central 业务报告 | 报告 → 业务报告 → 按 ASIN 明细 |
| 出单关键词、点击/转化份额 | 品牌分析 SQP | 品牌 → 品牌分析 → 搜索查询绩效 |
| 广告花费、ACOS、TACOS | 广告后台 | 广告报表 → 搜索词 / 推广的商品 |
| 历史价格与 BSR 曲线 | Keepa / 卖家精灵 | 商品页导出 CSV |

3. 在报告「数据质量」章节把缺口逐条列出，并说明缺口会**改变哪条结论**（例如"没有广告报表，无法判断增长来自自然流量还是烧钱"）。

## 三、合规红线

- 只采集公开页面或用户有权访问的数据。
- 不登录他人账号、不绕过验证码与付费墙、不违反目标站点 ToS。
- 用户提供的报表可能含账号敏感信息，报告里只引用指标，不复制账号、订单号、买家姓名等个人信息。
